Tours and Hints each have their own Stimulus controller, and both are driven entirely from
`data-action` attributes. Nothing here requires application JavaScript.

## Autostart

Tours default to `autostart=false`; Hints default to `autostart=true`. The asymmetry is deliberate: a Tour
takes the screen away from someone, a beacon does not.

```twig
<twig:Driver:Tour id="welcome" :autostart="true">
    ...
</twig:Driver:Tour>

<twig:Driver:Hints id="help" :autostart="false">
    ...
</twig:Driver:Hints>
```

Builders keep the same defaults: `ux_tour(tour)` renders a Tour that waits, and `ux_hints(hints)`
autostarts unless you pass `false` as the second argument.

## `once`

`once` is a UX Driver option, not a Driver.js one. With `:once="true"`, the controller writes
`ux-driver:seen:<id>` to `window.localStorage` and refuses to start that Tour again — autostart and manual
triggers both return early.

The flag is written at exactly one moment: when someone clicks the done button on the last Step. That
narrow rule has consequences worth knowing:

- Closing the Tour, pressing Escape, or navigating away leaves it unseen, so it comes back next time.
- Calling `preventDefault()` on the cancelable `ux-driver:done` event also prevents the write.
- If `localStorage` is unavailable — private browsing, blocked cookies, a full quota — the controller
  catches the failure, treats the Tour as unseen, and shows it again. The page keeps working; the Tour
  simply stops being once-only.

<Aside type="warning" title="`once` is per browser, not per user">
The flag lives in `localStorage`, so it does not follow someone to another device or survive a cleared
profile. When "shown once" is a product guarantee rather than a courtesy, store it server-side and render
the Tour conditionally.
</Aside>

Hints have no equivalent. Driver.js tracks dismissed beacons on the live instance only, and a reload
brings them all back.

## Restarting

`start` and `highlight` both destroy the current Driver.js instance before creating the next one, so a
second trigger always yields a clean Tour from Step one — unless `moveTo` sends it elsewhere.

## Tour actions

```twig
<button data-action="pentiminax--ux-driver--tour#start">Start tour</button>
<button data-action="pentiminax--ux-driver--tour#next">Next</button>
<button data-action="pentiminax--ux-driver--tour#previous">Previous</button>
<button data-action="pentiminax--ux-driver--tour#refresh">Refresh position</button>
<button data-action="pentiminax--ux-driver--tour#destroy">Close tour</button>

<button data-action="pentiminax--ux-driver--tour#moveTo"
        data-pentiminax--ux-driver--tour-index-param="2">Go to step 3</button>
```

`moveTo` requires the `index` param and counts from zero. Omitting it does nothing.

## Hints actions

```twig
<button data-action="pentiminax--ux-driver--hints#show">Show hints</button>
<button data-action="pentiminax--ux-driver--hints#hide">Hide hints</button>
<button data-action="pentiminax--ux-driver--hints#close">Close the open popover</button>
<button data-action="pentiminax--ux-driver--hints#restoreAll">Restore dismissed hints</button>
```

Four more actions take a `hintId` param. All eight, with their parameters, are in the
[Hints reference](/reference/hints/).
